WebWork

How to set a website up properly, from the first question

The stack changes with every project. The order does not. This is the sequence that keeps a site coherent: what to decide before anything is built, what to write down, what to build once, and how to check that any of it is true.

01

Five phases

02

Ask first. It changes everything downstream.

Twenty minutes of questions decides the stack, the content model, whether accounts exist at all, and how much of the budget goes to pictures. Ask in groups, and write the answers in the person's own words.

GroupWhat the answers decide
What this isThe home page's job, the primary action, what must not get worse
Who reads itWhich width you design first, hosting region, language, accessibility floor
The contentStatic files, a generator, or a database. Whether an editor is needed
MoneyWhether checkout exists. Whether a price may ever reach a public page
AccountsThe single largest scope fork in the project
MediaShot list, pipeline, licensing, and whether 3D is a second project
ConstraintsHosting shortlist, what gets cut, which launch blockers start now
After launchHow much can stay as code, and what earns an interface

Then name the shape: portfolio, editorial, catalogue with prices on request, shop, marketing, application, immersive. The shape sets every default that follows, and most projects are one shape plus a piece of another. Say which one wins when they disagree.

03

The two rules that carry most of the value

Anything that appears twice is built once. One definition, in one module, called by every screen. A variation is a parameter, never a second copy. The expensive bugs are never clever: they are the same element written three slightly different ways, in three files, so a fix lands in only one of them.

Check the built page, not the intention. Screenshots at three widths, contrast measured, overflow measured, console clean. An agent that cannot see the page it built will describe something that is not there, confidently.

04

Design outward from one page

  1. Type scale, proven against the longest real title at 320 and 1920.
  2. Colour: ink, paper, one accent, one muted ink. Contrast measured, not judged.
  3. Spacing and the frame: one scale, one maximum width, one section rhythm.
  4. One page, end to end, with real content. Not the home page: the page a visitor came for.
  5. Extract the components that page needed. The second time you need something, not the first.
  6. Motion last: two durations, one curve, and a reason for anything that loops.

A component library designed in the abstract is a guess. The same library extracted from a finished page is a record of what was actually needed.

05

What adapts per project

Hosting

Static host, edge platform, node host or managed platform. Decided by one question: does any page depend on who is asking?

Data

Files in the repository, a generator over a spreadsheet, edge SQL, managed Postgres, or a CMS. Start from needing none.

Accounts

None, an edge rule for staff, social providers, or email and phone with a password. Each brings its own recovery and linking rules.

Media

In the repository, object storage with transforms, or embeds. A shot list if items are photographed the same way.

3D

Only when a photograph cannot do the job. Budgets and a fallback before any modelling.

One platform

Hosting, database, storage, staff access and scheduled work from one vendor keeps the bill small and the moving parts few. Build on the free tier; expect to pay a little at launch.

Languages and messages

One source language, dictionaries for the rest, and a build that refuses to finish while a sentence is untranslated. Every email and text previewed in every language.

Generated imagery

The generator may improve a photograph. It may never invent the product. Write the fidelity contract first.

06

Gates, before anything is called done

GateThe measure
LayoutNo horizontal overflow at six widths; nothing important behind a fixed header
Type45 to 75 characters a line for body text
Colour4.5:1 for text, 3:1 for large text and control edges
KeyboardEvery control reachable, in order, with a visible focus ring
WeightFirst screen inside a budget written in the blueprint
ImagesDimensions or a ratio on every one; alt text that says something
ConsoleNo errors, no failed requests, no third party the reader did not ask for
CopyNothing addressed to the designer, nothing left as placeholder

Run node scripts/verify.mjs <page> after every visual change. It reports each of these and writes screenshots at three sizes.

07

More than one agent

Split by layer, not by feature. Name one lead, who decides disagreements and fixes what lands incomplete. The repository is the only channel: a claims table, a log entry per change, handoffs with exact field and secret names, and every commit pushed, because an unpushed commit is invisible. The same automated checks run on every push, whoever made it.

08

Starting

In an empty project folder, with the kit beside it:

  • node WebWork/scripts/new-project.mjs --name "Acme" --shape catalogue --into .
  • Answer the intake into docs/intake.md.
  • Write docs/blueprint.md from those answers.
  • Set the tokens, build one page, extract the components.

Or simply open the folder with an agent and say: read WebWork/START.md and take me through it.
